Embedded PDF variants

The same case as embedded-pdf.html, in the other shapes a real site can produce.

Each section is a separate embedded document, so each one has its own viewer. Chrome builds the identical embedder → viewer → plugin stack for every one of them; what differs is the element that hosts it and where it sits on the page.

1. <embed type="application/pdf">

Expect the same as an iframe: play reads the document from the top, words highlighted in place, no leftover blue selection.

2. <object type="application/pdf">

Expect the same again. <object> is the oldest of the three and still turns up in intranets and generated invoice pages.

3. Two different PDFs on one page

Expect each frame to read its own document, never the other one — every viewer reports the same internal address, so they can only be told apart by the file each renders. Read the left one (“Readalix reads PDFs aloud…”), stop, then read the right one (“Voyage…”). Also expect that pressing play with nothing selected starts exactly one of them, not both at once.

4. A PDF two frames deep

Expect no difference. The viewer is nested inside another element here (and could just as well be inside another iframe, as in a preview pane) — depth is not what the reader keys on.
