PDF at a URL with no .pdf extension

The shape a download endpoint uses — /download?id=8421 — instead of a plain file.pdf. Same document either way; only the address changes.

Why this page exists. Chrome opens its built-in PDF viewer from the response's Content-Type: application/pdf, so a PDF needs no .pdf in its address. Readalix has two ways of noticing a PDF: the content script asks the document (document.contentType, which is always right), while the popup and the background match the tab's address against /\.pdf(\?|#|$)/i, which these links defeat. So reading is expected to work here, and the popup is expected to be wrong — that is the thing to look for.

  • ./download?id=8421 — a query string, like a real download endpoint
  • ./download — the same file, bare
  • ./Readalix reads PDFs.pdf — the control: identical document, ordinary .pdf address
  1. Open a link with no extension and press play with nothing selected. The document reads from the top — “Readalix reads PDFs aloud…” — with each spoken word highlighted by the viewer, exactly as on the control link.
  2. Select a passage, then play. Only that passage is read, and the blue selection disappears as reading starts.
  3. Look at the popup on the extensionless links. The pick-element button is expected to be shown even though a PDF tab has nothing to pick, and the note explaining that play reads from the top is expected to be missing. Both are correct on the control link.
  4. Click the page while it reads stops it; Escape stops; the read shortcut toggles — on every link here.

Real examples of the same shape: https://arxiv.org/pdf/2401.12345 (no extension at all), attachment endpoints such as /mail/attachment?id=…, and invoice or statement downloads such as /documents/download?ref=….

Other PDF cases — a PDF inside an <iframe>, and the <embed>/<object>/nested variants — are on embedded-pdf.html and embedded-pdf-variants.html.
